# v0.20.0

## What the update brings

What differs from one machine to the next is stated in `.devcontainer/.env`,
which compose reads from the compose file's directory, so an editor's Reopen in
Container starts the container as `devcontainer up` does. `.env.podman` and
`.env.macos` are committed beside it, one per host the fleet runs, and `.env` is
the machine's own copy of one, which git ignores.

The host's NVIDIA GPUs are given to the container by
`docker-compose.nvidia.yml`, which `nvidia/devcontainer.json` merges over the
compose file as a second configuration, and `system/cuda.sh` installs the CUDA
toolkit where a host's `.env` turns `INSTALL_CUDA` on.
`scripts/check-devcontainer.py` holds every configuration under `.devcontainer/`
to the default's declaration.

## Steps by hand

- On every machine the workspace is worked on, copy `.devcontainer/.env` from
  `.env.podman` on a Linux host running Podman or from `.env.macos` on a Mac,
  and edit what differs there.
- Rebuild the devcontainer on every machine the workspace is worked on, so the
  container runs the image this version installs (an editor's Rebuild Container,
  or `devcontainer up --remove-existing-container`).
