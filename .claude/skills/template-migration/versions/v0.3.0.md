## What the update brings

A render carries the whole stack: the web app (`apps/web`, Vite, React and
TypeScript) beside the server, a Tauri desktop application behind a question and
its Android project behind a second one, and an Azure pipeline,
`azure-pipelines.yml`, running the gates. Kubernetes is rendered only for a
project that deploys to Azure Kubernetes.

An update brings the web app and, with the defaults, the desktop application
into a workspace beside what it already holds, and the devcontainer gains Node's
packages, the Tauri CLI and the webview libraries.

## Questions

It asks `deployment` (default `azure-k8s`), `tauri_desktop` (default `true`),
`tauri_android` (default `false`, asked only with the desktop application) and
`app_identifier` (default `app.<slug>`, asked only with the desktop
application). Their defaults render what `v0.2.0` did plus what is new; an
update run without `--defaults` asks them.

It derives `project_const`, `app_product_name`, `app_package` and
`app_package_path`, which are never recorded.

## Steps by hand

- Rebuild the devcontainer on every machine the workspace is worked on, so the
  container runs the image this version installs (an editor's Rebuild Container,
  or `devcontainer up --remove-existing-container`).
- Run `npm ci` once the merge lands, so `node_modules` holds the tree the merged
  `package-lock.json` records.
- Where the project runs its gates on Azure Pipelines, create the pipeline from
  `azure-pipelines.yml`; the documentation site's Building page gives the `az
  pipelines create` command.
