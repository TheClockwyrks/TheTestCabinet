# v0.35.1

<!-- cspell:words rustup -->

## What the update brings

A fix of the first pipeline runs on the `v0.35.0` CI images.

- `ci/images/web.Dockerfile` sets `RUSTUP_HOME` and `CARGO_HOME` to where the
  toolchain image installed Rust, as `rust.Dockerfile` does, and makes the
  directories of both writable by every user. `v0.35.0` put `/home/dev/.cargo/bin`
  on the image's `PATH` for the mold driver, which put rustup's cargo proxy on
  it as well, and a proxy run under the pipeline's `HOME`, which holds no rustup
  settings, answered that no default toolchain is configured. A gate or a shell
  test that runs cargo in the web image, such as a checks job's test of a
  script resolving a lock file, failed with that.
