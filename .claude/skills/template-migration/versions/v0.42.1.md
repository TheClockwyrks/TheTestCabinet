## What the update brings

The published images are built again with the SSH client's configuration,
`/etc/ssh/ssh_config.d/50-warn-weak-crypto.conf`, at mode `0644` whatever the
umask of the machine that built them.

- The amd64 images held it `0664`, since the heredoc that writes it took the
  build pool's umask of `002`, and OpenSSH refuses every connection while a
  configuration file it reads is writable by its group, with
  `Bad owner or permissions on /etc/ssh/ssh_config.d/50-warn-weak-crypto.conf`.
  Every fetch, push and submodule update over SSH, and every cargo fetch of a
  git dependency, failed inside an amd64 devcontainer. The arm64 images held
  it `0644` and were unaffected.
- `.devcontainer/docker-compose.yml`'s image references move to the new tags:
  the toolchain image and every language image the project builds on.
- `.devcontainer/README.md` states the file's mode under "SSH agent
  forwarding".

## Steps by hand

- Build the devcontainer image again, so the container runs on the fixed
  images. The update changes no file the running container reads.
- Until then, inside a running container,
  `sudo -n chmod 644 /etc/ssh/ssh_config.d/50-warn-weak-crypto.conf` lets ssh
  connect again for the container's life.
- Where the project edited an image reference in
  `.devcontainer/docker-compose.yml`, the merge leaves both versions between
  conflict markers: keep the project's edit with the new tag.
