# v0.2.0

<!-- cspell:words Nyxsis -->

## What the update brings

A render carries nothing that only the fleet's manager reads. The devcontainer
configuration drops the workspace label, the memory ceiling, the CPU weight and
the control group parent from its `runArgs`, and the clean command it declared;
the manager supplies each when it starts a container. The harness drops
`.claude/hooks/nyxsis-forward.sh` and every hook `.claude/settings.json`
registered for it. The gate holds a render to naming the manager nowhere.

## Questions

It stops asking `memory_max_gib`, `cpu_shares` and `clean_command`. Copier drops
their entries from `.copier-answers.yml` as it records `v0.2.0`; delete any that
remain.

## Steps by hand

- Recreate the devcontainer on every machine the workspace is worked on, so the
  container is started with what this version declares (an editor's Rebuild
  Container, or `devcontainer up --remove-existing-container`).
