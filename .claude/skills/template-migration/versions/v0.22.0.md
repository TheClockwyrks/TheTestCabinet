## What the update brings

The Mac's manual tunnel stays off a machine where the fleet's agent serves the
container runtime: `tools/macos-host-runtime.sh` refuses to start or run in the
foreground while the agent's runtime socket exists, at
`~/.local/state/nyxsis/runtime.sock` or where
`DEVCONTAINER_AGENT_RUNTIME_SOCKET` names it, and `--status` and `--stop` still
work. Inside the container, `tools/host-runtime.sh` tells a container given a
runtime credential whose runtime does not answer that the fleet configuration's
bridge has to hold the port. The devcontainer's README states both.

## Questions

It adds no question and stops asking none, so every recorded answer stays as it
is.

## Steps by hand

- On a Mac the agent serves the runtime on, stop a manual tunnel still holding
  the port with `.devcontainer/tools/macos-host-runtime.sh --stop`.
- Restart the devcontainer on every machine the workspace is worked on; its
  start scripts run from the checkout, so a restart takes them.
