# v0.24.0

## What the update brings

The CI images are tagged with the commit their pipeline runs on.
`scripts/ci/ci-image.sh build <track>` is the script's one subcommand, building
the track's image and pushing it as `<repository>:<commit>`; the input lists,
the digest and the tags file writer are gone. `ci/images/tags.yml` holds one
variable, `ciImageTag`, the full commit whose image pipeline run built the
images every gates job pulls, and every job of `azure-pipelines.yml` names its
track's image at that variable.

The template renders `ci/images/tags.yml` only where the workspace lacks it, so
an update leaves the workspace's older per-track tags in the file while the
pipeline reads `ciImageTag`.

## Questions

It adds no question and stops asking none, so every recorded answer stays as it
is.

## Steps by hand

- Once the merge is pushed, let the image pipeline's run on it push every image,
  then write that full commit id into `ci/images/tags.yml` as its one variable,
  `ciImageTag`, replacing the per-track tags the file held, and commit it. The
  `ci-tests` gate fails while the file holds anything else.
