## What the update brings

A fix of three failures of the first pipeline run on the `v0.34.0` CI images.

- Where the project builds the Android application (`tauri_android`), the JDK's
  bin directory is on the `PATH` of the devcontainer and of the Android CI
  image. `apksigner` and `keytool` exec `java` by name, and the published
  android image links no `java` into `/usr/bin`, so the APK's signature check
  failed with `java: not found`.
- The Rust job's build output cache gains a last restore key, the OS alone, so
  a run whose `rust-toolchain.toml` changed restores the newest build output
  rather than compiling the whole workspace cold. Cargo checks what it restored
  by fingerprint and rebuilds only what the change invalidated.
- The `rust-test` step sets `CARGO_BUILD_JOBS` to 1, so the hosted agent
  compiles one crate's test binary at a time, which its memory holds where two
  at once were killed. The tests still run in parallel under nextest.

## Steps by hand

- A project that builds the Android application: once the image pipeline has
  built the Android CI image on the commit holding the update, write that
  commit into `ci/images/tags.yml` as `ciImageTag` in a second commit, as
  `ci/images/README.md` describes, and rebuild the devcontainer image once on
  each machine, with **Rebuild Container** in the editor or
  `devcontainer up --remove-existing-container`.
- A project without the Android application has nothing to do; the pipeline's
  changes take effect on the update commit's own run.
