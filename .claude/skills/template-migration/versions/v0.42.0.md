# v0.42.0

## What the update brings

The push hook refuses a submodule pin that a landing of the pushed branch would
take to a branch it was never meant for. A landing lands a submodule on the
`branch` its `.gitmodules` entry names, so a repository whose entries name
`master` while its `nightly` pins its submodules' `nightly` commits had the
landing of `nightly` push the submodules' development work straight to their
`master`.

- `ci/gates/submodule-remotes.py`, for a push to the branch `<b>`, reads the
  `branch` the pinning commit's `.gitmodules` names for each submodule whose
  pin the submodule remote's branch `<b>` holds. Where that entry names a
  branch other than `<b>` and `.`, and that branch of the remote does not hold
  the pin, the push fails, naming the submodule, the pin, the branch named and
  that `<b>` holds it, with the two ways out: set the entry's `branch` to `.`,
  or pin a commit the named branch holds. A pin the named branch holds, a pin
  on a branch other than `<b>`, an entry naming `<b>`, `.` or no branch, and a
  push that updates no branch are held to the earlier rule alone. A named
  branch the remote lacks holds nothing; with the submodule not checked out, a
  named branch not standing at the pin is not judged. Nested pins are held to
  their own holder's `.gitmodules`.
- `ci/tests/test_submodule_remotes.py` holds such a pin to failing, and an
  entry naming `.`, the pushed branch or no branch, a pin the named branch
  holds, a pin on another branch and a nested pin's own entry to what the rule
  says of each.
- The hook's description in `.pre-commit-config.yaml`, the gate list in
  `CLAUDE.md`, the documentation's building page and `ci/README.md` state the
  new rule.
- `.cspell/project-words.txt` lists `TARGETPLATFORM` in every render, not
  only one with the desktop application, so a workspace rendered without it no
  longer fails `cspell` on the `FROM --platform=$TARGETPLATFORM` its
  devcontainer README has stated since v0.41.1.

## Steps by hand

- Read the `branch` each entry of `.gitmodules` names. One that names a fixed
  branch, such as `master`, while the repository's other branches pin that
  submodule's commits of their own namesake, such as `nightly`, now refuses
  each push of those branches; set it to `.`
  (`git config -f .gitmodules submodule.<name>.branch .`) so a landing of each
  branch lands the submodule on its namesake, and commit the change, or pin
  only commits the named branch holds.
- The rule is applied by the push hook, so a clone carrying no `pre-push` hook
  is not held to it; run `scripts/setup-hooks.sh` in one that lacks it, as the
  `v0.40.0` guide says.
- A pin already published that the rule refuses is not judged again, since the
  gate checks only the commits a push publishes; correct the entry or the pin
  before the next landing of the branch that published it.
