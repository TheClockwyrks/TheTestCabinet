# v0.37.0

## What the update brings

The gates check a checkout that sits under a `.git` directory, as a worktree
added under the repository's own `.git` does, as they check any other, and a
lint gate that finds no file to check fails saying so.

- `cspell.json` anchors its ignores to the checkout's root: `/.git/**` in place
  of `**/.git/**`, and `/**/node_modules/**`, `/**/target/**`, `/**/build/**`
  and the rest of the patterns that opened with `**/` the same way. cspell
  matches a pattern opening with `**` against the whole path, so `**/.git/**`
  left out every file of a worktree under `.git`, and `**/build/**` every file
  of a checkout under a `build` directory, and cspell then printed its usage
  and failed.
- `.markdownlint-cli2.yaml` keeps its ignores, which markdownlint-cli2 reads
  from the checkout's root, and its comment says so.
- `apps/web/vite.config.ts` names `server.fs.deny` itself: Vite's list, with
  the repository's own `.git` in place of Vite's `**/.git/**`, which refused
  every file of a worktree under `.git` to the web app's test suite.
- The `ci` library carries `run_lint`, which runs a lint tool, echoes what it
  said and fails the gate naming the tool where the number of files it states
  it checked is zero or absent, saying an ignore pattern not anchored to the
  root is the usual cause, without cspell's usage text, and its two halves,
  `files_checked` and `require_files_checked`. `run` takes `combine`, which
  collects stderr with stdout. The `cspell` and `markdownlint` gates run their
  tool through `run_lint`, so markdownlint-cli2 linting no file no longer
  passes.
- `ci/tests/test_gates_in_a_worktree.py` copies the workspace into a throwaway
  repository, adds a worktree of it under its `.git`, and holds the `cspell`
  and `markdownlint` gates to checking the same files in both, the gates to
  failing with their reason where the configuration leaves them no file, and
  the web app's suite to running there. It is skipped where the npm workspace
  is not installed. `ci/tests/test_proc.py` covers the helpers.
- `ci/README.md` and the documentation's building page describe the check.

## Steps by hand

- A project that edited `cspell.json`'s `ignorePaths` keeps each ignore it added
  anchored to the root: `/vendor/**` for a directory at the root, and
  `/**/<name>/**` for one at any depth, never a pattern opening with `**/`.
- A project that edited `apps/web/vite.config.ts` keeps `fs: { deny: FS_DENY }`
  in its `server` options where the merge left a conflict there.
- A gate of the project's own that runs a lint tool reading a list of globs can
  run it through `run_lint`, naming the pattern its summary states the number
  of files in.
