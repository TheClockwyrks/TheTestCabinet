# v0.6.0

## What the update brings

The devcontainer is declared through a compose file,
`.devcontainer/docker-compose.yml`, which `devcontainer.json` names. The hook
scripts are replaced by a `ci/` project holding one file per gate under
`ci/gates/` and the runner that reports on them, and `azure-pipelines.yml` runs
each gate as a step of its own inside CI images that a second pipeline,
`azure-pipelines-ci-images.yml`, builds through `scripts/ci/ci-image.sh`. An
update brings all of it and removes the scripts it replaces.

## Questions

It asks `ci_registry`, the registry the CI images are pushed to and pulled from,
defaulting to `registry.example.com`. It derives `project_module`, which is
never recorded.

## Steps by hand

- Rebuild the devcontainer on every machine the workspace is worked on, so the
  container runs the image this version installs (an editor's Rebuild Container,
  or `devcontainer up --remove-existing-container`).
- Where the project runs its gates on Azure Pipelines, create the image pipeline
  from `azure-pipelines-ci-images.yml` as a second pipeline (the documentation
  site's Building page gives the command), let it push the images, and write
  each track's tag, which `scripts/ci/ci-image.sh tag <track>` prints, into the
  `resources.containers` block of `azure-pipelines.yml`.
