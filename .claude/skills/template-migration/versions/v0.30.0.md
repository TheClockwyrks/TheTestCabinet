## What the update brings

The two glibc targets are linked with `mold`. `languages/rust/mold.sh` installs
it from its release archive, checked against `MOLD_SHA256_AMD64` or
`MOLD_SHA256_ARM64` beside `MOLD_VERSION` in the compose file's anchor, and
installs `cc-mold` beside it. The devcontainer, Rust and Android Dockerfiles set
`CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_LINKER` and
`CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER` to `cc-mold`; a musl or an
Android target keeps its own linker, and `.cargo/config.toml` is left as it is.

The workspace manifest's `[profile.dev]` keeps line tables alone as a
development build's debug info, and `CLAUDE.md` forbids putting the CPU under
artificial load to provoke a flaky test.

## Steps by hand

- Rebuild the devcontainer on every machine the workspace is worked on, so the
  container runs the image this version installs (an editor's Rebuild Container,
  or `devcontainer up --remove-existing-container`).
- Where the merge changed a file the image pipeline triggers on (its path filter
  in `azure-pipelines-ci-images.yml` is the one list of them), push the merge,
  let the image pipeline's run on it push every image, then write that commit
  into `ciImageTag` in `ci/images/tags.yml` and commit it. The gates run in the
  images the old pin names until that second commit lands.
