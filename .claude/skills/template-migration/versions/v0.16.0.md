# v0.16.0

## What the update brings

Each browser instance of the web app's test configuration writes its attachments
into a directory of its own beneath the gate's artifact directory, so a failed
test's screenshot is not overwritten by the other instances. The web job's
browser tests step names that directory, and two steps after it publish it as
the build artifact `web-browser-test-<attempt>` and its JUnit report as test
results, whether the suite passed or failed.
