# v0.20.2

## What the update brings

The same fix for the project's own deploy steps: the deployment job hands
`.azure/project/deploy-steps.yml` the connection as a `serviceConnection`
parameter beside the phase. The template renders that file only where the
workspace lacks it, and the render check holds it to declaring the parameter.

## Questions

It adds no question and stops asking none, so every recorded answer stays as it
is.

## Steps by hand

- Where the workspace has its own `.azure/project/deploy-steps.yml` from before
  this version, declare the `serviceConnection` parameter in its `parameters`
  beside the phase, as the file the template renders does, and sign in through
  it.
