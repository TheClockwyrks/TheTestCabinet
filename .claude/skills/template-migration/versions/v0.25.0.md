# v0.25.0

<!-- cspell:words Nyxsis -->

## What the update brings

The template asks only the questions whose answers decide which of its shapes a
project takes, and derives every other value by the fleet's conventions. It
renders every file: `_exclude` names no seed and no file is skipped because it
exists, so what a project changes in a rendered file, the commit
`ci/images/tags.yml` pins among it, survives an update through the three-way
merge rather than through an answer. The stages its questions are asked in are
declared in `.nyxsis/template.toml` at the template's root, which no render
carries.

## Questions

It stops asking `seed_files`, `rust_test_hook`, `nextest_overrides`,
`extra_gates`, `python_projects`, `drain_skill_notes`, `extra_git_ignores`,
`pipeline_repositories`, `pipeline_extensions`, `nix`, `static_musl`,
`extra_tools`, `rust_ci_packages`, `extra_ignored_paths`,
`spelling_ignore_patterns`, `markdown_line_length`, `markdown_title_in_body`,
`deploy_branch`, `deploy_overlay`, `manual_overlay` and `image_platform`.

It derives `ci_registry`, `image_registry`, `web_dev_port`, `deploy_namespace`,
`deploy_environment`, `azure_resource_group`, `azure_cluster` and
`azure_service_connection` rather than asking them, by the conventions the
template's README states.

Copier drops every one of those entries from `.copier-answers.yml` as it records
`v0.25.0`, and the template's render check fails an answers file that records
any of them.

## Steps by hand

- Delete from `.copier-answers.yml` the entry of every question listed above
  that is still there: `seed_files`, `rust_test_hook`, `nextest_overrides`,
  `extra_gates`, `python_projects`, `drain_skill_notes`, `extra_git_ignores`,
  `pipeline_repositories`, `pipeline_extensions`, `nix`, `static_musl`,
  `extra_tools`, `rust_ci_packages`, `extra_ignored_paths`,
  `spelling_ignore_patterns`, `markdown_line_length`, `markdown_title_in_body`,
  `deploy_branch`, `deploy_overlay`, `manual_overlay` and `image_platform`, and
  the derived `ci_registry`, `image_registry`, `web_dev_port`,
  `deploy_namespace`, `deploy_environment`, `azure_resource_group`,
  `azure_cluster` and `azure_service_connection`.
- Where the workspace had answered any of them away from its default, the merge
  rendered the old version with that answer and the new one by the convention,
  so it carried the answer's content out of the workspace. Updating by hand,
  avoid that by deleting those entries from `.copier-answers.yml` and committing
  before the update, so the old version renders by the convention and the
  content stays as the workspace's own edit. Once the merge has landed, restore
  from the commit before the update (`git diff HEAD`, `git checkout HEAD --
  <path>`) what such an answer rendered, as the workspace's own edit: a gate of
  its own, a uv project, a `.gitignore` line, an ignored path, a deployment
  value, a seed the project owned.
- Where the workspace answered `nix`, `static_musl` or `extra_tools`, the
  devcontainer and CI images change: rebuild the devcontainer on every machine,
  and where the merge changed a file the image pipeline triggers on (its path
  filter in `azure-pipelines-ci-images.yml` is the one list of them), push the
  merge, let the image pipeline's run on it push every image, then write that
  commit into `ciImageTag` in `ci/images/tags.yml` and commit it. The gates run
  in the images the old pin names until that second commit lands.
