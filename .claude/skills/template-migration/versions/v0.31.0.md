## What the update brings

cargo's heavy subcommands run under a permit from the fleet's agent, so the
workspaces on one machine take turns building.
`languages/rust/permit-wrapper.sh` places a wrapper named `cargo` in
`~/.local/bin`, ahead of the toolchain's own on the `PATH`, which runs `build`,
`check`, `clippy`, `doc`, `test` and `nextest` through the `permit` subcommand
of the agent's executable at `/nyxsis/harness/bin/<platform>/nyxsis-agent` where
that executable is in the container and `NYXSIS_WORKSPACE` names the session's
workspace, and runs everything else as it is. `languages/rust/rustup.sh` no
longer puts `~/.cargo/bin` first on an interactive shell's `PATH`.

The drain-issues-queue skill no longer asks agents to serialize heavy commands
with `flock`, and it and `CLAUDE.md` state that the wrapper coordinates them.

## Steps by hand

- Rebuild the devcontainer on every machine the workspace is worked on, so the
  container runs the image this version installs (an editor's Rebuild Container,
  or `devcontainer up --remove-existing-container`).
- Where the workspace's own shell configuration puts `~/.cargo/bin` ahead of
  `~/.local/bin`, take it out, so `cargo` resolves to the wrapper.
- The image pipeline triggers on `.devcontainer/languages/rust`, though the CI
  images do not run the wrapper: where the merge changed a file the image
  pipeline triggers on (its path filter in `azure-pipelines-ci-images.yml` is
  the one list of them), push the merge, let the image pipeline's run on it push
  every image, then write that commit into `ciImageTag` in `ci/images/tags.yml`
  and commit it. The gates run in the images the old pin names until that second
  commit lands.
