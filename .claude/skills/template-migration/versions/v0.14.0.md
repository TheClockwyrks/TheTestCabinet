# v0.14.0

<!-- cspell:words venv -->

## What the update brings

The render catches up with what the workspaces had moved ahead of it: the web
gates' JUnit and coverage reports, a `rust-doctest` gate, the strict ESLint rule
sets, `uv_project()`, the `/api` proxy carrying WebSockets with both of its ends
movable through the environment, Cargo's resolver 3, Vite 8, every CI image's
`/root` widened for the uid Azure runs a container job's steps as, and the newer
skills and finished-issue hook. Every image build is handed the commit as a
build argument, and `scripts/ci/deploy.sh` runs the project's
`scripts/ci/post-deploy.sh` where one exists. The prose and format gates leave
`.venv`, `build` and `tmp` alone, and cspell reads `.gitignore` and no
configuration but its own.

The web app's sample files are renamed to `app.tsx`, `app.test.tsx` and
`app.browser.test.tsx`, and its test setup files move under `src/test/`. The
documentation site's sidebar moves out of `apps/docs/astro.config.mjs` into
`apps/docs/site.config.mjs`, which renders the same sidebar. The CI image tags
move out of `azure-pipelines.yml` into `ci/images/tags.yml`, which the template
renders only where the workspace lacks it, with a placeholder tag.

## Questions

It asks `seed_files`, `server_serves_web`, `server_name`, `rust_test_hook`,
`nextest_overrides`, `extra_gates`, `python_projects`, `drain_skill_notes`,
`pipeline_repositories`, `pipeline_extensions`, `nix`, `static_musl`,
`extra_tools`, `extra_ignored_paths`, `spelling_ignore_patterns`,
`markdown_line_length`, `markdown_title_in_body` and `web_dev_port` of every
project, and `deploy_branch`, `deploy_overlay`, `manual_overlay`,
`deploy_namespace`, `deploy_environment`, `azure_resource_group`,
`azure_cluster`, `azure_service_connection` and `image_platform` of a project
that deploys to Azure Kubernetes. Every default renders what `v0.13.0` did, so
an update run with `--defaults` changes nothing a default decides.

It derives `server_package` and `server_module`, which are never recorded.

## Steps by hand

- Rebuild the devcontainer on every machine the workspace is worked on, so the
  container runs the image this version installs (an editor's Rebuild Container,
  or `devcontainer up --remove-existing-container`).
- Run `npm ci` once the merge lands, so `node_modules` holds the tree the merged
  `package-lock.json` records.
- Where the workspace had edited the web app's `src/App.tsx`,
  `src/App.test.tsx`, `src/App.browser.test.tsx`, `src/test-setup.ts` or
  `src/browser-setup.ts`, carry the edit into the renamed file (`src/app.tsx`,
  `src/app.test.tsx`, `src/app.browser.test.tsx`, `src/test/setup.ts` or
  `src/test/browser-setup.ts`) and delete the old file wherever the merge left
  it.
- Run `scripts/ci/ci-image.sh tag` once the merge lands, which writes every
  track's tag into `ci/images/tags.yml`, and commit it; `ci/images/README.md`
  gives the order to push the tag and queue the gates in.
