## What the update brings

A project learns to claim the cloud resources it deploys to, which Nyxsis
reads for their health, state and cost and shows on the project's Cloud page.

- The `nyxsis` skill, `.claude/skills/nyxsis/SKILL.md`, carries a `[cloud]`
  section: the table's `resource_groups`, `r2_buckets` and `pages_projects`
  keys, each a list of at most 32 names, that Nyxsis reads the table from
  `.nyxsis/project.toml` on the primary remote's default branch rather than
  from a checkout, what makes it malformed, and what the Cloud page shows for
  a claim. The section on `.nyxsis/project.toml` says the table alone is read
  from the default branch.
- `.nyxsis/project.toml` declares an empty `[cloud]` table under a comment
  naming the skill, its three keys commented out. An empty table claims
  nothing, as no table does.

## Questions

It adds no question and stops asking none, so every recorded answer stays as it
is.

## Steps by hand

- A project that already declares a `[cloud]` table keeps its own where the
  merge left a conflict, with the comment above it, and drops the commented
  keys it fills in. Two `[cloud]` headers in one file are not TOML, and a file
  that is not TOML is unreadable for every key.
- A project that deploys to a cloud names every resource group, R2 bucket and
  Pages project holding something it deploys in the table, and commits it to
  the default branch. A managed cluster's node resource group is claimed
  through the cluster and is not listed.
