# Create the contracts repo and move the shared contracts into it

This issue follows the v0.7.0 tag. Populate the `contracts` repository
(`git@ssh.dev.azure.com:v3/genyume/the-test-cabinet/contracts`) with every data
contract The Test Cabinet shares with gg, the Spec
Cabinet and any harness, so that each of those depends on one dependency-free
repository rather than on The Test Cabinet's core crate.

## Current state

`packages/run-record` and `packages/asset-contract` are TypeScript packages
generated by `crates/contract-codegen` from Rust types that live in
`crates/core`. The `contract-drift` CI job regenerates them and fails on a
difference, and `scripts/ci/seeded-contract-check.sh` checks that the copy
vendored into a model's workspace matches.

gg depends on `test-cabinet-core` as a path dependency, and what it imports is
one surface: the `gg` module family (`GgAgentConfig`, `GgCapabilitySet` and the
`CAPABILITY_*` constants, `GgRunLimits`, `GgTelemetryEvent` and
`GgTelemetryKind`, `GgCallFailure`, `GgContextSource`, `GgProgramLanguage`),
`gg_session_record`, `gg_session_journal` and the `metrics` types. Nothing else
in core is reached from gg. The console's richer views of a gg run are driven
entirely by what those types carry.

The test-suite format types are modelled in core on `feat/the-spec-cabinet`.

## Design

### Scope of the repository

The contracts repository holds data structure definitions, interfaces and
traits, and the validation logic that decides whether a value of one of those
shapes is well formed. It holds no other logic. It depends on serialization and
schema crates only, and on no repository of this project.

### What moves

The Rust types behind `run-record` and `asset-contract` move into a contracts
crate. `crates/contract-codegen` moves with them, and the two generated
TypeScript packages are committed in the contracts repository beside the crate
that generates them, so a consumer receives the Rust and TypeScript shapes from
one tag.

The harness contract moves as its own module of the same crate: the `gg` type
family, the session record and journal formats, and the metrics types. This is
the telemetry interface a harness implements to have its runs rendered with the
views the console gives gg runs today. The interactive successor to gg adopts
it first, which is what lets The Test Cabinet evaluate that harness against gg
for regressions, and a third-party harness can adopt it the same way.

The test-suite format types join the crate when `feat/test-suites` lands; see
[`split-the-spec-cabinet-into-its-own-repository.md`](split-the-spec-cabinet-into-its-own-repository.md).

`packages/run-stats` stays in The Test Cabinet, since scoring is logic.

### Consumption

Cargo consumers declare the contracts crate as a git dependency on the Azure
repository pinned to a tag. npm consumers declare the generated packages the
same way. The `contract-drift` gate moves to the contracts repository's own
Azure pipeline, which regenerates the TypeScript packages and fails on a
difference. `seeded-contract-check.sh` stays in The Test Cabinet, since it
checks the vendored copy in a produced workspace.

The contracts pipeline mirrors to GitHub after its gates, as The Test Cabinet's
does.

This issue precedes
[`extract-gg-into-its-own-repository.md`](extract-gg-into-its-own-repository.md).

## Done when

- [ ] The contracts crate holds the run record, asset contract and harness
      contract types, and `contract-codegen` generates `run-record` and
      `asset-contract` from it in the contracts repository.
- [ ] `crates/core` depends on the contracts crate for those types and
      declares none of them itself.
- [ ] `crates/gg` builds against the contracts crate with no dependency on
      `test-cabinet-core`.
- [ ] The web console and site consume the generated packages from the
      contracts repository at a pinned tag.
- [ ] The contracts pipeline runs the drift gate and mirrors to GitHub.
- [ ] The docs describe the contracts repository as the source of the shared
      shapes, and `CLAUDE.md` points there.
- [ ] Gates green in both repositories.
